样本按 1.3× 呈现以便标注。取三行而非一行，是因为 1 与 4 讲的是「跨行重复」， 单行看不出来。

  1. 1

    面包屑父群名独占一整行，且连续重复

    octo - matter v2 产研 在截图里连续出现 3 次，各占一整行 18px。 它回答「在哪里」，但连续三行答案相同，第二三次是纯噪音。 → 降级为标题行前缀（L2）／连续折叠（L3）

  2. 2

    「这是子区」被编码了三遍

    面包屑有父群名、标题前有 〰 图标、另一类行还在预览里写 [子区]。 三个信号同义。→ 删图标与文字前缀，位置和前缀已足够表达

  3. 3

    头像子角标在 40px 下不可读

    右下角 14px 的群组小图标，在实际尺寸下只是一团灰点，且与面包屑重复表达「这是群里的」。 → 删

  4. 4

    同父群的头像完全相同

    三个子区行共用一个 产研 头像，重复三次却不提供区分度。 → L3 折叠后子行不再重复头像，改用一条缩进竖线

  5. 5

    发送者前缀规则不统一

    群与子区行有 牛奶:，AI 助手行没有。同一列出现两种语义， 读者要先判断这段文字是「谁说的」还是「说了什么」。 → 保留但统一：仅多人会话显示

  6. 6

    时间与未读角标竖直堆叠

    右侧两行各放一个，吃掉整行高度。但时间是背景信息、角标才是行动信号， 两者优先级不同却给了同等空间。 → 同行右对齐；有未读时角标压过时间

  7. 7

    AI 徽章连续出现四次

    四个 AI 助手连续排列，每个都挂 AI 标签，而它们的头像本身已高度可辨识。 → 删标签；如需分区，用一条分组标题代替四个徽章

02

一次活动，两行上榜

这不是啰嗦，是会让人点错的结构问题。子区里来了消息，会同时产生 子区自己的行 和 父群的行（父群的「最后一条消息」正是那条子区通知）。 于是 web ui 回滚 以两种身份、两个时间出现，读者无法判断该点哪一个。

04

L3 与已实现的排序功能互斥

只能二选一，原因在 CSS 而不在设计

已实现的「按重要性排序」用 order 改变视觉顺序，DOM 顺序保持不变。 而 L3 的「连续同父群折叠」必须知道「上一行是不是同一个父群」， 这在 CSS 里只能用相邻兄弟选择器表达，而它看的是 DOM 顺序。

两者同开会错位：DOM 里相邻的两行，视觉上可能被 order 拆到列表两端， 于是折叠会隐藏错误的行——用户看到的是「某个子区莫名没有父群名」。

L1 与 L2 都只改行内表达、不依赖行间关系，因此与排序功能完全兼容。 建议先发 L1 + L2，把 L3 作为「排序关闭时才可用」的互斥选项，或等确认分组比排序更有价值再取舍。
