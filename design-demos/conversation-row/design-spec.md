# 侧边栏会话行 · 信息架构精简设计 Spec

## 正确范围

本轮设计对象是 `octo-help` 插件对 Octo Web 侧边栏「最近」栏会话行的**呈现层**改造，不是向 `Mininglamp-OSS/octo-web` 提交源码。目标站只作为 DOM、字段与配色的事实来源。设计只处理「一行里显示什么、怎么排布」，不改变会话数据本身，也不改变点击后的导航行为。「关注」栏不在范围内：它渲染的是 compact 行且支持拖拽排序，本轮完全不触碰。原型见同目录 `index.html`，样本数据、配色与行高全部取自 2026-08-10 的真实截图（628×1360 @2x，面板宽 314px，实测三行子区行 68px、两行普通行 52px、列表可视高约 640px）。

## 问题定义

一个会话行只需回答三个问题：是谁、发生了什么、要不要我现在处理。现状每行最多承载九个信号——面包屑父群名、头像、头像子角标、子区图标、标题、时间、未读角标、发送者名、预览文本——其中只有未读角标与时间在回答第三个问题。多余的信号不是均匀分布的噪音，而是集中在三处重复：父群名在截图里连续独占三整行；「这是子区」被面包屑、`〰` 图标和预览里的 `[子区]` 前缀编码了三遍；四个 AI 助手连续排列且每个都挂 `AI` 徽章，而它们的头像本身已高度可辨识。

现状还有一处不是啰嗦而是会让人点错的结构问题。子区来消息时会同时产生子区自己的行和父群的行，因为父群的「最后一条消息」正是那条子区通知。于是 `web ui 回滚` 以两种身份、两个时间出现在列表里（18:15 的子区行与 14:29 的父群行），读者无法判断该点哪一个。这一条必须靠归并解决，删装饰无济于事。

## 三级方案与判定依据

方案分三级递进，每级可独立发布，判定依据是「删掉这个信号后，三个问题是否仍能回答」。

**L1 减装饰**删除纯冗余的视觉元素：`〰` 子区图标（面包屑已表达所属）、`AI` 徽章（头像已表达身份）、头像右下角 14px 子角标（该尺寸下不可读且与面包屑同义），并把预览里的 `[子区] xxx` 改写成人话「子区『xxx』有新消息」。同时把时间与未读角标合并到标题行右侧，让优先级更高的角标压过时间，而不是各占一行。这一级不涉及任何行间关系，与已实现的「按重要性排序」完全兼容，风险为零。

**L2 收面包屑**在 L1 基础上取消面包屑独占的那一行，把父群名缩短后并入标题行做前缀。父群名的作用是消歧而非标识，缩短到可辨识即够。同时执行上一节的归并规则：父群行若其预览只是子区通知，则不单独成行，把时间与真实预览留给对应的子区行，使点击目标唯一。这一级把全表统一到两行 52px，消灭 68px 的异类行高，一屏从 11 行增加到 13 行；同样不依赖行间关系，与排序功能兼容。

**L3 连续折叠**把连续同父群的行合并到一个分组表头之下，子行缩进并用一条竖线连接。表头聚合该组未读数，所以折叠后依然知道里面有事。头像的处理需要区分：同一父群的多个子区共用同一个头像，隐藏是净收益；而 AI 助手各自的头像是它们唯一的身份，隐藏会让若干行退化成空白，因此改为缩小保留。这一条区分是原型迭代中发现的——初版对所有子行一律隐藏头像，渲染后 AI 分组变成三行无差别的纯文字，随即修正。

## L3 与排序功能互斥

L3 不能与已实现的「按重要性排序」同时启用，原因在 CSS 而不在设计。排序用 `order` 改变视觉顺序而保持 DOM 顺序不变；L3 的「连续同父群」判断只能用相邻兄弟选择器表达，而它看的是 DOM 顺序。两者同开会错位：DOM 里相邻的两行可能被 `order` 拆到列表两端，折叠于是隐藏错误的行，用户看到的现象是「某个子区莫名没有父群名」。因此建议先发 L1 与 L2，把 L3 作为「排序关闭时才可用」的互斥选项，或等实际使用后确认分组比排序更有价值再二选一。

## 实现约束

映射回插件时，所有 `.wk-*` 选择器必须先进 `utils/octoSelectors.ts`，这是 eslint 强制的。L1 与 L2 的绝大部分是删除与位移，可用纯 CSS 在 `body[data-octo-*]` 门控下完成，沿用 `octoComposerEnhancer.ts` 的形态；但预览文案改写（`[子区] xxx` → 人话）与父群行归并需要读取行内容并判断，属于 JS 工作，且归并涉及隐藏 React 渲染的行，需要按 `octoConvSort.ts` 头注释里的理由用属性而非 class 标记状态。L3 需要相邻兄弟选择器加一个 `data-octo-parent` 盖章，因此必然引入 MutationObserver，与当前「零 JS」的排序功能不是一个量级，应单独评估。

## 输出与验收

原型为单页 `index.html`，以 1440×900 桌面端为主，四栏并排展示现状与三级方案，使用同一份真实数据。四栏总宽 1340px，超出正文栏宽，因此对比区做全出血处理；需确认 1440 下四栏无裁剪（`.compare` 的 `scrollWidth - clientWidth` 应为 0），1024 下退化为横向滚动而非压缩。拆解图用真实大字号而非 `transform: scale()` 呈现——缩放会把标注一同缩掉，初版正是因此让所有标注叠在文字上。控制台错误为零。用户确认方案层级后再把规则映射回插件；当前阶段不修改任何 `utils/*.ts`。
